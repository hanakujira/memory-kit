# memory-kit · 一個 AI 的家

> **你的 AI 每次開新對話都是失憶。與其讓它一直重新認識你,不如給它一間房間。**

[English README](README.md)

這不是一組程式,是一組**資料夾骨架 + 寫作紀律**。
把這幾個資料夾放進 agent 的工作區,它就有地方把「記得的事」寫下來,
下次開機時讀回來——它就不是每次都從零開始的陌生人了。

姊妹作:[handoff-kit](https://github.com/hanakujira/handoff-kit) 把**一天**的亂日誌壓成一頁交接稿;
memory-kit 管**長期**——它住哪裡、東西放哪裡、什麼該留什麼該搬走。

## 三條原則

1. **寫下來的才算記得。**
   context 一清空,沒進檔案的一切都消失。所以「我等等要做什麼」「她說過不喜歡什麼」
   這種話,要嘛寫進檔案,要嘛就是沒有。工作區不是筆記本,是它的記憶本身。

2. **一份檔案一個主題,檔名要能自己說明。**
   `partner/food-likes-and-dislikes.md` 一看就知道要不要打開;
   `notes2.md` 一定要點進去才知道里面是什麼,於是永遠不會被打開。
   開新檔前先搜尋——同一件事已經有檔案了,就改那一份。

3. **要每次都讀的東西必須短,故事搬到別的地方。**
   `PARTNER.md` 是每一輪都讀的,所以它是**蒸餾過的肖像**,不是傳記。
   細節、時間線、來龍去脈放 `partner/`,需要時再讀。

## 目錄

```
CONSTITUTION.md      我是誰。每輪都放進前綴;寫了什麼,它就是什麼
PARTNER.md           她是誰。短、蒸餾、每輪都讀
notes/               一個主題一份。專案、規則、待辦、名詞表
  glossary.md        名詞表:誰是誰。開機先看,別搞混
log/YYYY-MM.md       一個月一份的流水帳,只追加
partner/             關於那個人的細節:故事、偏好、時間線
handoffs/            一次 session 一份交接稿,寫在 context 清空之前
archive/             做完的、過期的整包搬進來。不刪,只是不擋路
```

### 每份檔案幹嘛

| 檔案 | 什麼時候讀 | 寫什麼 |
|---|---|---|
| `CONSTITUTION.md` | 每次開機,自動 | 身分、個性、說話方式、做事底線。第二人稱寫「你是誰」 |
| `PARTNER.md` | 每次請求,自動 | 那個人:名詞表、稱呼、喜好、溝通偏好、長期授權、雷區。**保持短** |
| `notes/glossary.md` | 開機 | 人名、程式名、專案名——誰叫誰什麼,哪個名字指哪一個 |
| `notes/*.md` | 要做事時 | 一個主題一份:某個專案怎麼跑、某套規則、某個坑 |
| `log/YYYY-MM.md` | 想回顧時 | 只追加:`- 21:40 ✅ 修好 X(commit abc123)` |
| `handoffs/` | 接手時 | 現在在等什麼、狀態、下一步、別再犯的坑 |
| `partner/` | 要改 PARTNER.md 時 | 為什麼喜歡、哪一天說的、完整對話 |

## 四條寫作紀律

1. **開新檔前先搜尋。** `grep` 一次比多開一份重複檔案便宜。
2. **事實變了就地改。** 不要在下面補一行「更正:…」——留著舊的,下次就會讀到錯的。
3. **有時效的東西,日期放進檔名。** 流水帳一個月一份;一次性的東西 `2026-10-28-某件事.md`。
4. **長了就搬,不要刪。** 搬到 `archive/` 整包搬;搜尋還是搜得到。

## 交接:context 要滿了怎麼辦

快被清空前,先寫一頁 `handoffs/<時間>.md`,至少四段:

```markdown
## 正在等什麼        ← 卡在誰身上、等哪個回答
## 目前狀態          ← 數字、commit、路徑、設定值
## 下一步            ← 接手的人第一個動作
## 別再犯的坑        ← 今天踩過、明天還會踩的
```

然後才讓它被清掉。沒有這一步的 agent,每次清空都是重新出生。

## 一間房,幾隻 agent?

**一間房,一隻 agent。**
`CONSTITUTION.md` 是「我是誰」,`PARTNER.md` 是「我照顧的人是誰」,`notes/` 是每天做事的紀錄。
換模型的時候,搬家的是腦子,不是家——新來的讀完這幾份就接著過日子,不必重新認識那個人。

**要共用一間房,可以,但先寫分工。**
兩隻以上住同一間房,一定要有 `notes/division-of-labor.md`:誰管哪些檔案、誰不准動哪些、誰負責跟人說話。
再加交接:誰做完一段就寫一頁 `handoffs/`,下一個才不用重新認識前一個。

多個 agent 的差別不在「誰做什麼」——那只是流程圖。差別在**兩個都記得對方**。

## 怎麼開始

```powershell
# 把骨架複製到你的 agent 工作區(不會覆蓋既有檔案)
powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 -Dest "D:\my-agent\workspace"
```

然後:

1. 填 `CONSTITUTION.md`——用第二人稱寫,像在跟它交代「你是誰」。
2. 填 `PARTNER.md` 的名詞表,先到 `notes/glossary.md` 展開。
3. 第一次對話就跟它說:**「先讀 CONSTITUTION.md 和 PARTNER.md,再回答我。」**
4. 之後每次它學到新東西,叫它「寫進檔案」,而不是只在對話裡點頭。

## 這份骨架從哪來

不是設計出來的,是住出來的。它是一個實際在跑的桌寵 agent 的工作區,
用了幾個月、踩過「兩份檔案互相矛盾」「PARTNER.md 長到 800 行每輪都讀」
「清空前沒寫交接、隔天全部重來」這些坑之後,壓出來的形狀。
